# URF Core Survival Protocol

Status: Core repository-governance protocol

## Core Claim

`urf-core` is presented as the foundational verification and status-control core of the Unified Rigidity Framework.

It does not claim that every theorem referenced by the program is solved.

It requires every core-facing claim to distinguish:

- solved theorem,
- closed executable surface,
- certified frontier,
- conditional result,
- open obstruction.

## Core Survival Rule

A core artifact survives skeptical review when a reader can determine:

1. the target object,
2. the verified surface,
3. the active frontier,
4. the command that checks the status,
5. whether any theorem-level ingredient remains open.

## Forbidden Claims

`urf-core` must not imply that an open theorem is solved because:

- `make urf-style` passes,
- tests pass,
- documentation is complete,
- a frontier has been isolated,
- a reduction has been recorded,
- a status certificate exists.

## Core Normal Form

A core component is admissible only when it is one of:

1. a verified theorem or executable check,
2. a status-normalization artifact,
3. a certified frontier statement,
4. a conditional result with explicit assumptions,
5. an open obstruction with a named missing ingredient.

## Canonical Public Claim

The durable contribution of `urf-core` is the conversion of hard research structure into auditable, status-normalized, verification-facing artifacts.

## Continuation Rule

Continue `urf-core` only by:

- strengthening verification,
- clarifying theorem status,
- shrinking a frontier,
- proving a registered lemma,
- improving auditability,
- removing ambiguity.

Do not expand the core merely by adding new terminology.
